Detection Service API

Sentinel-1 VV+VH GeoTIFF in → oil-slick detections as GeoJSON out. For Ved (hindcast seeding) and Parth (backend orchestration). No authentication. All coordinates WGS84.

BASE = https://vscimatic999--oiltrace-detection-web.modal.run

Before you integrate — three things to know

  • Cold start: the service sleeps when idle (free hosting). The first request after ~5 quiet minutes takes an extra 20–40 s while the container wakes; requests after that are normal speed. Set client timeouts to ≥120 s, and fire one warm-up call (GET /health) a minute before any live demo.
  • Live inference takes ~20–60 s per 2048² scene (CPU). Parth: treat POST /detect as a long call or an async job — never a UI-blocking request. The cached demo endpoint is instant.
  • GeoJSON axis order is [longitude, latitude] (RFC 7946) in all polygon coordinates. The centroid property is a {lat, lon} object — named keys, no ambiguity.

GET/health Parth · liveness

Liveness probe and warm-up target. Returns immediately once the container is up.

{"status": "ok", "model_loaded": true, "device": "cpu"}

GET/ info

Service and model metadata: experiment name, checkpoint epoch, full validation metrics, default threshold, endpoint list. Useful for logging which model version produced a result.

GET/detect/demo Ved · start here

Instant (pre-computed, no inference): the detection result for the bundled demo scene — a real 267 km² slick in the Eastern Mediterranean. Identical schema to a live POST /detect response, so Ved can build and test the hindcast integration against this before any live call.

curl {BASE}/detect/demo

GET/demo/scene test fixture

Downloads the demo GeoTIFF itself (24 MB, 2-band VV+VH, georeferenced) — use it to round-trip test POST /detect end to end.

POST/detect the main endpoint

Runs the full pipeline on an uploaded scene: tiled U-Net inference → stitched probability map → threshold → minimum-area and confidence filters → polygons → WGS84 geometry.

Request

PartRequirement
file (multipart form field) GeoTIFF, exactly 2 bands (band 1 = VV, band 2 = VH), Sigma0 in dB, georeferenced (CRS + affine transform present). Max 80 MB. Any scene size works; 2048×2048 is typical.
threshold (query, optional) Probability cutoff, 0.05–0.95. Leave it out — the default 0.325 was selected on validation. Only override for experiments.
# curl
curl -m 300 -F "file=@scene.tif" {BASE}/detect -o result.geojson

# Python
import requests
with open("scene.tif", "rb") as f:
    r = requests.post(f"{BASE}/detect", files={"file": f}, timeout=300)
detections = r.json()

Field guide (what Ved consumes)

FieldMeaning & use
features[]One Feature per detected slick, sorted largest-first. Empty array = no oil detected — a valid, common result on clean water.
geometryThe slick outline in WGS84, [lon, lat] order. Polygon or MultiPolygon. Use for particle seeding across the slick area and for map display.
centroidSlick centre — the primary backward-drift seed point. Validation: median ~85 m from truth on matched slicks.
area_km2Computed in the slick’s UTM zone (metres), never in degrees. Scales particle count / spill volume assumptions.
confidenceMean model probability over the slick’s pixels, range 0.60–1.0 (detections under 0.60 are filtered out server-side). An uncalibrated model score, not a probability of oil — display as “detection confidence”. ≥0.75 is typically a solid detection; 0.60–0.70 deserves an “uncertain” tag in the UI.
centroid_inside_sceneSanity flag; should always be true.
No observation timestamp in the output. The dataset’s TIFFs carry no acquisition time, so the service cannot provide one — generated is processing time, not sensing time. Ved: take the scene’s observation time from scene metadata alongside the upload; Parth: carry observation_time as a separate field in the orchestration layer. For the cached demo scenario, agree one fixed timestamp as part of the demo bundle.

Integration checklist

Ved (hindcast)

  • Build against GET /detect/demo first — stable, instant, real data.
  • Seed backward drift from centroid; optionally scatter particles across geometry weighted by area.
  • Handle features: [] (no detection) and MultiPolygon geometry.
  • Attach the scene observation time yourself (see warning above).

Parth (backend)

  • Proxy /detect as an async job; poll-or-callback to the frontend. Client timeout ≥300 s, one retry on timeout.
  • Warm the service with GET /health on your app start and before demos.
  • The response is already RFC 7946 GeoJSON — validate with your Pydantic contracts as-is; properties.model gives you model-version provenance for logging.
  • For the judged demo, cache /detect/demo’s response in Supabase per the cached-bundle plan — the live call is the encore.
